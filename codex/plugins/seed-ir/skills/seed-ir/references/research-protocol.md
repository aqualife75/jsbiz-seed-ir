# 외부 근거·논문·이미지 조사 · v1.5.1

이 조사는 제출 자료의 빈칸과 투자자 검수 결함을 해결하기 위한 범위 기반 조사다. 웹 전체와 모든 논문을 빠짐없이 확인했다는 의미의 전수조사는 선언하지 않는다. 무엇을 어디까지 확인했는지 검색 행렬로 보여준다.

## 먼저 분류할 것

| 공백 | 확인 경로 |
|---|---|
| 시장 규모·추이, 인구·사업체 수 | 공식 통계와 공공 데이터, 원문 보고서 |
| 경쟁사 가격·사양·기능 | 경쟁사 공식 제품·가격·도움말 페이지. 확인 시점 기록 |
| 기술 원리·효과·성능 가능성 | 논문 원문, 등록 시험, 원 데이터와 연구 방법 |
| 팀 매출·유료 고객·계약·실험 결과 | 팀의 내부 자료와 담당자 확인 |
| 실제 제품·현장·고객 사진 | 팀이 보유하거나 권리 확인한 실제 사진 |
| 설명용 외부 이미지 | 원본 자산 페이지와 재사용 조건 |

외부 산업 자료는 회사 실적을 입증하지 않는다. 타사 연구에서 효과가 있어도 자사 제품의 임상·안전·성능 검증으로 바꾸지 않는다. 팀 이름 검색으로 비공개 계약·매출을 추정하지 않는다.

## 검색 행렬

각 중요한 주장마다 `gap_id`, 질문, 적용 목차, 검색어(한국어/영어 또는 관련 언어), 조사 경로, 기간·지역·대상 범위, 채택 근거, 반대 증거, 남은 한계를 기록한다. 핵심 투자 논점은 가능한 경우 독립적인 일차 자료로 교차 확인한다. 한 자료만 있거나 같은 원 출처를 재인용한 자료뿐이면 그 제한을 적는다.

사용 가능한 검색·브라우저·논문 커넥터를 사용한다. 특정 유료 앱이나 API를 필수로 요구하지 않는다. 로컬 지침이 브라우저 도구를 지정하면 해당 도구를 우선한다. 온라인 조사 도구가 없다면 확인한 로컬 원문만 분석하고 온라인 미조사 범위를 남긴다. 이때 `research`는 `pending`이며, 가능한 초안 산출을 계속한다. 실행하지 않은 쿼리나 검색 결과를 로그로 만들지 않고 로컬 분석만으로 외부조사 통과를 주장하지 않는다.

기본 `project.json`의 `research_required: true`를 유지한다. 도구 부재나 접근 제한은 외부조사 면제 사유가 아니다. 사용자가 외부조사를 제외한 범위를 명시한 경우에만 총괄이 요청과 적용 범위를 기록하고 `false`로 바꿀 수 있다. 조사 에이전트가 임의로 설정을 변경하지 않는다.

검색 결과의 요약에서 멈추지 말고 채택할 원문을 연다. 실제로 읽은 문장·쪽·표를 기록한다. 자료의 발행일과 검색 확인일을 구분하고 수치의 기준 연도를 함께 저장한다. 링크가 열리지 않거나 유료 원문을 읽지 못했으면 초록 수준 확인으로 표시하고 원문 전용 수치를 확정하지 않는다.

## 논문을 채택할 때

다음 항목을 `research/papers.json`에 기록한다.

- 제목, 저자, 발행연도, DOI 또는 영구 URL, 출판 상태(심사논문·프리프린트·수정·철회 여부).
- 연구 대상과 표본 수, 모집 방법, 연구 설계, 비교군과 대조 조건.
- 실제 측정한 결과, 효과크기·불확실성, 해당 표/그림/쪽, 재현 조건.
- 자사 기술·고객·사용 환경과 연구 환경의 차이. 인과관계인지 상관관계인지 구분.
- 연구의 한계, 연구비와 이해상충, 실제 읽은 원문 범위.
- IR에 사용할 정확한 주장과 사용할 수 없는 주장.

초록만 읽었으면 `full_text_read: false`를 남긴다. 유의확률 하나만으로 사업 효과를 단정하거나 작은 실험 표본을 전체 고객군으로 일반화하지 않는다. 원문에 없는 연구 방법·표본·이해상충을 만들어 채우지 않는다.

## 상충 자료와 조사 종료

상충 자료를 버리지 말고 정의·시점·지역·측정 단위·표본 차이를 비교한다. 같은 현상에 대한 결론이 다르면 슬라이드에서 적용 범위 또는 가정으로 한계를 표시한다. 한 가지 유리한 수치만 고르지 않는다.

검색 종료는 질문별로 판단한다. 정한 경로와 언어의 검색을 수행했고, 현재 주장에 충분한 원문을 확인했거나 추가 쿼리가 새 근거를 주지 않는 상태를 기록한다. 시간·접근 제한으로 멈추면 미조사 경로와 남은 쿼리를 적는다. 제한을 기록한 것은 근거가 확보된 것과 다르다.

## 실제 검색 로그 계약

`research/search-log.json`은 최소 다음 구조를 갖는다. 모든 항목은 실제 조사 결과로 채운다.

```json
{
  "scope": "확인할 주장·지역·기간·문헌 범위",
  "limitations": "접근하지 못한 원문과 미해결 논점",
  "queries": [
    {
      "query": "실제로 입력한 검색어",
      "engine": "실제로 사용한 도구 또는 검색 엔진",
      "accessed_at": "실제 확인 일자",
      "selected_urls": [],
      "excluded": [],
      "notes": "선정·제외 이유와 검색 결과의 범위"
    }
  ],
  "gaps": [
    {
      "id": "G01",
      "question": "확인할 질문",
      "status": "disclosed",
      "disclosure_slide_id": "S05",
      "resolution": "이 장표에서 표시한 한계와 후속 검증 계획"
    }
  ]
}
```

공백이 실제로 해결되면 `status: resolved`를 쓴다. 미해결 공백을 장표에 명시했으면 `disclosed`와 현재 `deck/deck.json`에 실제로 존재하는 `disclosure_slide_id`를 쓴다. 해당 장표에서 한계를 직접 읽을 수 있어야 한다. 핵심 사실이 해결되지 않았다면 투자자 검수에서 여전히 P0/P1로 판단할 수 있다. 로그 필드를 채웠다는 이유만으로 중요한 결함을 해결 처리하지 않는다.

## 이미지와 사진

사용자가 이미지 검색을 따로 요청하기 전에도 현재 장표의 주장과 visual-plan을 보고 원본·공식 근거 이미지가 필요한 곳을 조사한다. 장식 이미지 수집보다 제품 작동부·공식 수치·현장 맥락을 설명하는 자료를 우선한다. 장표별 source_strategy, evidence_ids, claim_boundary와 search_note 보완 후보를 디자이너에게 인계한다. 전체 계획과 생성 자산의 경계는 [시각 제작 절차](visual-production.md)를 따른다.

원본 페이지 URL, 저작자, 라이선스 문구 또는 허가 기록, 확인일, 재사용 조건, 변형 여부, 관련 주장을 자산대장에 저장한다. 검색 미리보기 이미지를 최종 자산으로 쓰지 않는다. 오픈액세스 논문도 개별 그림에 다른 권리가 있을 수 있어 확인한다.

다운로드·재사용이 허용되고 도구 정책이 허용하는 자산만 프로젝트 안에 저장한다. 원본 비율·캡션·출처를 유지한다. 권리를 확인할 수 없거나 적합한 이미지가 없으면 자산은 후보로 남기고, 확인한 사실 데이터의 native 차트·표·관계 도식을 제작할 수 있게 원문과 값을 인계한다. 제품·현장 맥락에 필요한 설명 이미지는 디자이너가 확인한 설계 범위에서 전문적으로 기획·생성하도록 제작 요구를 함께 인계한다. 데이터의 공개와 원문 그래픽의 재사용 조건을 구별한다. 도식의 범위·비율·가정은 원문 근거를 따라야 한다.

이미지가 필요 없는 계산·일정·검증 구조는 native를 선택하고 search_note에 이미지 미사용 이유를 적을 수 있다. 조사한 경우에는 실제 검색어·원문·채택/제외·권리 미확인 사유를 남긴다. 도구 부재는 검색 성공이나 외부조사 면제로 기록하지 않는다.

생성 이미지는 확인한 설계·사용 상황을 설명하는 자산이다. 필요한 제품 사진·화면 기획은 디자이너와 연결하되 실제 구현·실험·고객 반응의 근거로 사용하지 않는다. 자산 대장에는 source·rights·origin·caption·claim_boundary와 현재 파일 SHA256을 기록하고, 실제 장표 blocks/visual_brief의 path에 연결한다. 생성 자산의 상위 disclosure와 caption에는 AI·생성·설계·예시 상태를 읽히게 표시한다. 사업 실증 공백은 가정의 설명만으로 resolved가 되지 않는다.
