v1.5.0 환경 준비와 결과 게시

새 프로젝트에서는 Codex가 load_workspace_dependencies로 Python·Node·라이브러리 경로를 확인하고 준비 스크립트를 실행합니다. 아래 명령은 Codex 내부 실행 예시이며 교육생이 복사할 명령이 아닙니다. Python은 찾은 실행 파일을 사용하고 NODE_PATH와 MODULES_PATH는 실제 발견한 경로로 바꿉니다.

python .agents/skills/seed-ir/scripts/prepare_project.py --project . --team "우리팀" --install-missing --node "NODE_PATH" --node-modules "MODULES_PATH"

준비 상태와 실행 경로는 work/setup/runtime.json의 ready, python, node, node_modules에 기록됩니다. 첫 준비에는 인터넷과 Codex의 권한 승인이 필요할 수 있습니다. 실패하면 Codex가 오류를 확인하고 복구하며 교육생에게 터미널 명령을 맡기지 않습니다. 신규 자료 위치는 자료넣는곳이며 기존 프로젝트는 설정된 입력 폴더를 유지합니다.

두 덱의 실제 렌더와 현재 근거를 검수한 뒤 Codex가 다음 명령으로 결과를 모읍니다.

python .agents/skills/seed-ir/scripts/publish_results.py --project .

결과물/날짜-고유ID/에 한글 이름의 PPTX·대본·질문·검수 보고서를 저장하고 결과물/결과보기.html에서 최신 결과를 안내합니다. 현재 원고의 구조 검사, 투자자 검수(pass/revise), 시각 검수(pass), 피칭 검수(pass)와 지문을 확인합니다. 실제 final 검사에 따라 초안 또는 완료로 표시하며, 미검수·오래된 렌더는 게시하지 않습니다.

시각 검수 기록에는 실제로 확인한 렌더 이미지의 render_sha256 맵을 발표본은 기록 루트에, 상세본은 views.master에 각각 저장합니다. 키는 프로젝트 상대 경로, 값은 SHA256이며 실제 PPTX 렌더를 눈으로 확인한 뒤 계산합니다. 실행만으로 시각 검수를 대신할 수 없습니다.

01

압축을 풀고, 팀 프로젝트를 설치하세요

팀마다 새 폴더 하나를 만듭니다. 설치 후에는 그 폴더를 Codex에서 열어 작업합니다.

설치 전 준비

  • Codex와 로컬 로그인컴퓨터의 프로젝트 폴더를 여는 Codex 환경이 필요합니다. 각자 이용 중인 계정과 사용 한도를 따릅니다.
  • Python 3.11 이상Windows에서는 py -3 --version, macOS에서는 python3 --version으로 확인합니다.
  • Node.js와 artifact-tool 런타임복합 PPTX 제작은 Codex 환경의 @oai/artifact-tool을 사용합니다. 자동 탐색 후 실제 PPTX를 렌더해 확인합니다. 특정 유료 앱은 필수가 아닙니다.
  • 인터넷과 조사 도구첫 의존성 설치와 공식 자료·논문 조사에 필요합니다. 연결되지 않은 기능은 미완료로 남깁니다.

설치되는 곳

배포 폴더 바깥의 새 프로젝트를 사용하세요. 기존 프로젝트 파일이 있으면 덮어쓰지 않고 중단합니다.

my-seed-ir/
├─ .agents/skills/seed-ir/
├─ .codex/agents/
├─ AGENTS.md
├─ .venv/
├─ input/
└─ output/

--with-deps를 붙이면 프로젝트 안에 가상환경을 만들고 문서 처리 라이브러리를 설치합니다. 사용자 전역 Codex 설정은 수정하지 않습니다.

  1. 받은 ZIP 파일을 전부 압축 해제합니다.

    ZIP 안에서 직접 실행하지 마세요. install.py와 이 설명서가 함께 있는 폴더를 엽니다.

  2. 해당 폴더에서 터미널을 열고 설치합니다.
    py -3 install.py --project ../my-seed-ir --team "우리팀" --with-deps

    py가 없고 python이 설치되어 있다면 python install.py로 바꿉니다. --team 뒤에는 팀 이름, --project 뒤에는 새 폴더명을 넣습니다. 경로에 공백이 있으면 따옴표로 감싸세요.

  3. 간편 실행도 가능합니다.

    install-windows.cmd를 더블클릭하면 배포 폴더 옆 my-seed-ir에 기본 팀 이름 My Team으로 설치합니다. 팀명을 지정하려면 위 명령을 사용하세요.

  4. 설치 완료 메시지의 프로젝트 폴더를 Codex에서 엽니다.

    배포 파일이 들어 있는 폴더와 구분하세요. 새 프로젝트에 input, output, AGENTS.md가 있으면 준비된 상태입니다.

  1. 받은 ZIP 파일을 전부 압축 해제합니다.

    터미널에서 install.py가 있는 배포 폴더로 이동합니다.

  2. 새 팀 프로젝트를 설치합니다.
    python3 install.py --project ../my-seed-ir --team "우리팀" --with-deps

    --team 뒤에는 팀 이름, --project 뒤에는 새 폴더명을 넣습니다. 간편 실행은 sh install-macos.sh이며 기본 팀 이름은 My Team입니다.

  3. 설치 완료 메시지의 프로젝트 폴더를 Codex에서 엽니다.

    프로젝트 안의 가상환경은 .venv/bin/python으로 실행합니다. 가상환경을 활성화하지 않아도 이 경로로 호출할 수 있습니다.

의존성 설치 중 인터넷 오류가 났다면

프로젝트는 이미 만들어졌을 수 있습니다. 같은 설치 명령을 반복하지 말고, 오류 메시지에 안내된 가상환경의 -m pip install -r requirements.txt 명령으로 라이브러리 설치만 재시도하세요.

복합 장표 런타임 확인

설치한 팀 프로젝트에서 Codex에 “PPTX 런타임을 확인해 줘”라고 요청하세요. 아래는 Windows 가상환경 기준이며 macOS/Linux는 첫 경로를 .venv/bin/python으로 바꿉니다.

.venv/Scripts/python.exe .agents/skills/seed-ir/scripts/render_deck.py --check-runtime

사용 가능하면 Node와 artifact-tool 경로를 출력합니다. 없으면 Codex에 load_workspace_dependencies로 번들 경로를 찾도록 요청하세요. SEED_IR_NODE는 Node 실행 파일, SEED_IR_NODE_MODULES는 @oai 폴더를 포함한 node_modules 디렉터리를 가리킵니다. 아래 경로는 직접 확인한 실제 경로로 바꾸는 예시입니다.

자동 탐색이 실패했을 때 경로 지정하기
$env:SEED_IR_NODE = 'C:\실제경로\node.exe'
$env:SEED_IR_NODE_MODULES = 'C:\실제경로\node_modules'
export SEED_IR_NODE='/실제경로/node'
export SEED_IR_NODE_MODULES='/실제경로/node_modules'

설정한 터미널에서 런타임 확인 명령을 다시 실행하세요. 런타임을 준비하지 못하면 제작 단계를 미완료로 두고 원문·근거·질문 초안을 보존합니다. Python의 --with-deps가 이 Node 런타임을 설치하지는 않습니다.

02

한 팀의 자료를 input 폴더에 모으세요

참가신청서와 사업계획서뿐 아니라 인터뷰 기록, 고객·매출 데이터, 실험 결과, 제품 화면, 팀 소개, 견적서도 넣을 수 있습니다. 자료가 갱신되면 기준 날짜와 단위를 함께 남기세요. 사용자 지정 외부 폴더는 읽을 수 있지만, 추적과 검수는 프로젝트 input/ 사본을 기준으로 합니다. 선택한 한 팀만 복사하고 원본은 수정하지 않습니다. 원래 폴더가 바뀌면 사본도 갱신하세요. 여러 팀의 자료를 하나의 덱에 섞지 않습니다.

파일가져오는 정보확인이 필요한 부분
PPTX / DOCX본문과 내장 이미지, 슬라이드·문단 위치도형·표의 시각적 관계, 페이지 번호, 차트 해석은 원본 화면과 대조합니다.
XLSX시트의 셀 위치, 저장된 값과 수식, 연결된 이미지수식을 다시 계산하지 않습니다. 최신 계산값·기간·단위를 확인하세요.
HWPX섹션·문단 텍스트, 내장 이미지실제 페이지 구분과 표·그림 배치는 렌더 화면을 확인합니다.
HWP 5설치된 hwpjs 우선, 없으면 olefile 기반 본문·BinData 추출대체 추출은 표 구조·이미지 배치·페이지 위치를 보존하지 못합니다. 암호·배포 보호·구형 문서는 PDF/HWPX로 내보내세요.
PDF페이지별 텍스트와 이미지, 텍스트 없는 페이지의 검토용 이미지스캔 페이지는 OCR/시각 확인 대기에 남습니다. 자동으로 읽혔다고 간주하지 않습니다.
TXT / MD / CSV / TSV / JSON행별 텍스트와 원본 위치CSV는 원본 행을 보존합니다. 구분자·열 의미·숫자 단위는 에이전트가 해석하고 검증합니다.
PNG / JPG 등 이미지원본 이미지, 파일 지문과 위치이미지의 의미와 글자는 별도 시각 검토가 필요합니다. 읽지 않은 수치는 만들지 않습니다.

지원하지 않거나 손상된 파일도 목록에 남습니다. 중복 파일은 SHA256으로 식별하고 같은 내용을 반복 추출하지 않습니다. 대형 파일과 위험한 압축 구조는 제한하고 이유를 기록합니다.

디자인 샘플이 있다면

사용 권한이 있는 참고 PPTX를 design/에 넣고 Codex에 파일 위치를 알려주세요. 제목·본문 크기, 색, 여백, 이미지 배치 규칙을 분석해 반영합니다. 참고 자료와 팀의 실제 근거 자료는 구분하세요.

배포 파일에 포함되지 않는 것

배포본에는 사용자 소유의 가상 사업 글루코픽(GlucoPic) 예시와 승인된 교육용 자산을 포함합니다. 실제 참가팀 자료·분석 결과와 원본 교안·폰트 파일은 포함하지 않습니다. 가상 인터뷰·반응·인물·가격·성과·전망은 실제 팀 자료로 바꿔야 합니다.

외부 자료로 채울 수 있는 것과 팀이 확인할 것

시장 통계·기술 배경·경쟁 정보는 외부 조사로 보강할 수 있습니다. 우리 팀의 매출, 고객 수, 제품 성능은 팀 자료가 필요합니다. 자료가 없으면 필요한 자료와 질문을 남깁니다. 실제 계획과 가정은 표시할 수 있지만 없는 실적을 가정으로 채워 완료시키지 않습니다. 필수 데이터가 비어 있으면 초안은 가능하고 최종본은 보완을 기다립니다.

03

새 작업에서 이 문장을 입력하세요

Codex에서 설치된 my-seed-ir 프로젝트를 연 뒤 새 작업을 시작합니다. 아래 내용을 복사하고 필요한 조건만 덧붙이세요.

복사가 막히면 전체 선택 후 Ctrl+C / ⌘C

팀의 단계, 초기 고객, 제품 구현 상태, 제출 마감, 참고 디자인 경로를 추가하면 초안의 초점이 더 분명해집니다. 외부 검색은 환경에 연결된 검색·브라우저 도구로 수행합니다. 원본 이미지·표의 직접 확인에 필요한 도구와 의존성을 먼저 점검하고, 사용할 수 없는 기능은 대기 작업에 남깁니다.

자료를 추가했거나, 중간에 멈췄다면

$seed-ir 현재 상태와 input 변경을 확인하고 미완료 단계부터 재개해 줘. 질문별 답·논거와 상세본·발표본을 함께 갱신하고 영향받는 투자자·시각·피칭 검수를 다시 수행해 줘.

검수 후 수치나 본문이 바뀌면 해당 검수를 다시 해야 합니다. 이전 통과 기록만으로 새 덱의 완료를 판단하지 않습니다.

사용자 지정 순서는 표지 → 문제 배경 및 최근 트렌드 → 문제 정의 → 기존 대체재의 문제점 → 해결방안 → 제품 및 서비스 소개 → 초기 고객 반응 → 수익 모델 → 시장 규모 → 초기 시장 진입 전략 → 성장 전략 → 마일스톤 → 팀 구성 → 비전이다. 문제 정의·기존 대안·제품 소개·초기 시장 진입은 각각 독립 장표 2개 이상, 나머지는 1개 이상으로 master와 pitch 각각 최소 18장을 만든다. 초기 고객 확보와 이후 성장을 분리하며 기존 대안 2장은 문제 정의 뒤·해결방안 앞에 둔다. 이번 교육 범위에서는 투자 요청·조달·금액·사용 계획을 덱·대본·질문에 넣지 않는다. 마일스톤은 목표·일정·산출물·검증 기준으로 구성한다.

04

v1.5.0: 근거 선택부터 실제 화면까지

장표마다 결론·주요 증거·읽는 순서를 먼저 정합니다. 제품은 실제 화면 또는 설계안임을 밝힌 이미지로 사용 순간과 행동을 설명합니다. 외부 이미지가 필요하면 공식 원문과 재사용 권리를 확인합니다. 공개된 이미지라는 이유만으로 배포하지 않습니다.

  2. 양쪽 덱 전장 검수: 내보낸 실제 PPTX를 다시 읽어 렌더하고 상세본·발표본의 각 장을 개별 확인합니다. 글자 넘침·겹침·누락·크롭·차트 라벨에 더해 정보 위계·증거 가독성·연속 구성 변화를 기록합니다. 축소 모아보기나 자동 검사만으로 대체하지 않습니다.

  3. 근거
    투자자 관점에서 원문이 주장을 지지하는지 대조합니다. 내부 확인과 외부 조사를 나누고 공식 자료·논문·상충 증거를 검토합니다.
  4. 복합 시각화
    표·차트·제품 화면·산식을 함께 구성합니다. 문제–해결 대응, 제품 여정, 경쟁표, 검증 일정처럼 내용의 관계가 보이는 구조를 고릅니다.
  5. 상세본
    master에 충분한 설명과 증거를 보존합니다. 최소 18장과 목차별 최소 장수를 지키며 필요한 장표를 추가하고 질문별 논증을 검수합니다.
  6. 300초 발표본
    pitch에 핵심 흐름을 선택·압축합니다. 상세본 근거와 연결한 상태로 두 PPTX의 실제 화면과 발표 대본을 검수합니다.

08

막혔을 때 확인할 곳

설치 명령이 Python을 찾지 못합니다.

Python 3.11 이상을 설치하고 터미널을 다시 여세요. Windows에서 py -3와 python 중 동작하는 명령을 사용합니다. --version 결과가 3.11 이상인지 확인하세요.

“기존 파일을 보존했습니다”라고 나옵니다.

이미 설치된 폴더에 재설치하려 했을 수 있습니다. 기존 팀 작업은 그 폴더를 Codex에서 열어 재개하세요. 새 팀은 --project ../another-team-ir처럼 다른 새 폴더를 지정합니다.

$seed-ir 또는 커스텀 에이전트가 보이지 않습니다.

설치된 팀 프로젝트를 열었는지 확인하고 새 작업을 시작하세요. .agents/skills/seed-ir/SKILL.md와 .codex/agents/가 있어야 합니다. “프로젝트의 AGENTS.md와 seed-ir SKILL.md를 읽고 실행해 줘”라고 요청할 수 있습니다. 하위 에이전트가 지원되지 않으면 역할을 순차 수행하고 그 사실을 기록합니다.

HWP에서 표나 사진 위치를 정확히 읽지 못합니다.

HWP5 대체 추출기는 문단과 이미지 파일을 꺼내는 데 초점을 둡니다. 원본 HWP를 PDF 또는 HWPX로 내보내고 다시 넣어 주세요. 표의 행·열 관계와 수치는 렌더 화면을 보고 확인해야 합니다. 암호·배포 보호 문서는 보호를 우회하지 않습니다.

인터넷 조사나 이미지 검토 도구가 없습니다.

Codex에서 사용 가능한 도구가 있어야 해당 검사를 수행할 수 있습니다. 연결이 안 된 상태에서는 누락된 조사·판독 작업을 대기로 남기고, 진행 가능한 초안을 작성합니다. 외부 조사를 임의로 면제하거나 수행하지 않은 온라인 로그를 만들지 않습니다. 찾지 않은 출처나 보지 않은 이미지의 내용을 만들어 넣지 않습니다.

폰트가 바뀌거나 PPTX에서 글자가 잘립니다.

샘플에 쓰인 폰트 파일은 배포하지 않습니다. 사용 권한이 있는 폰트를 별도로 설치하거나 사용할 수 있는 한글 폰트로 바꿔야 합니다. 폰트 변경 후 실제 PPTX를 다시 렌더하고 줄바꿈·넘침·차트 라벨·그림 자르기를 재검수합니다.

수정이 반복되는데 중요한 근거가 계속 없습니다.

동일 결함의 자동 수정은 기본 2회까지 시도합니다. 이후에는 부족한 데이터와 필요한 팀의 결정을 기록합니다. 출처 없는 수치를 임의로 채워 검사를 통과시키지 않습니다. 확인할 수 있는 자료를 추가하고 재개하세요.

실제 자료를 읽을 때 자주 만나는 함정

  • 제품 화면의 숫자는 시연 데이터일 수 있습니다. 가격·점수·사용자 수를 화면에서 읽었다는 사실만으로 실제 매출이나 검증 결과가 되지 않습니다.
  • 시장 통계는 분모부터 맞춥니다. 산업 전체 금액이 곧 우리 서비스의 시장은 아닙니다. 복수 응답 비율·기준 연도·대상 업종과 지불 의사 조건을 확인하세요.
  • 현재 실적과 이력을 분리합니다. 이전 회사나 참여 프로젝트의 성과는 팀의 관련 경험이 될 수 있지만 현재 회사의 고객·투자 유치 실적은 아닙니다.
  • 표를 추출해도 행·열 관계는 확인해야 합니다. HWP 대체 추출에서 문단 순서와 그림 배치가 사라질 수 있습니다. 중요한 숫자는 원본 화면·표와 대조하세요.
  • 목표와 현재 성과를 구분합니다. 마일스톤은 일정·담당·산출물·검증 기준을 연결합니다. 없는 결과를 목표 숫자로 꾸며 실제 성과처럼 표시하지 않습니다.
  • 개인정보는 IR 근거와 구분합니다. 서명·연락처·증명서의 불필요한 정보는 공개 덱에서 제외하고 사업에 필요한 경력만 확인합니다.
