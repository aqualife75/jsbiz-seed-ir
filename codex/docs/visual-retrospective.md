# 시각화가 부족한 IR에서 배운 제작 기준

한 IR 제작에서는 목차와 논거를 갖춘 뒤에도 표와 카드가 반복되어 제품과 사업 구조가 충분히 드러나지 않았다. 개선 과정에서 중요했던 것은 이미지 개수보다 각 주장을 어떤 시각 관계로 보여 줄지 먼저 결정한 일이었다. 이 문서는 일반화할 수 있는 절차만 기록하며 특정 팀의 자료·수치·인물·생성 자산을 공개하거나 사업 검증 완료를 주장하지 않는다.

## 내용을 그림으로 옮기기 전에 관계를 정한다

문제의 현장에는 상황이나 관찰 근거를, 기존 대안에는 동일 조건 비교를, 제품에는 핵심 작동부를 사용했다. 시장은 모수·교집합·채널 계산으로, 고객 검증은 서로 다른 분모의 경로로, 일정은 목표·산출물·진행 기준으로 표현했다. 팀 근거가 부족한 곳에는 가짜 프로필 대신 확인할 역할과 책임을 보여 주었다.

이런 선택을 장표별 계획으로 먼저 정리하면 같은 카드에 문장을 넣는 방식에서 벗어날 수 있다. 다만 시각 계획을 저장하는 것만으로 화면이 바뀌지는 않는다. 제작기가 계획을 반영하고 실제 렌더가 읽는 순서와 근거를 보여 주는지 확인해야 한다.

## 생성 이미지는 설명을 돕고 사실의 공백은 남긴다

제품 사진·화면·생활 장면은 여러 장표에서 재사용할 핵심 자산으로 기획했다. 생성된 결과를 직접 읽자 요청한 동작과 다른 장면이 보이는 경우가 있어 사용 위치를 다시 정했다. 화면의 예시 수량·시각·요일 표시는 사용 실적으로 해석하지 않았고, 제품 설계와 구현 상태를 구별한 캡션을 유지했다.

원본·공식 근거 이미지는 출처와 재사용 조건을 확인한다. 조건을 충족하지 못하면 확인한 사실 데이터의 편집 가능한 차트·표나 관계 도식을 선택한다. 모든 장표에 사진을 넣거나, 모든 부족한 근거를 생성 이미지로 채우는 방식은 필요하지 않다.

## 대표 화면 다음에 양 덱 전체를 읽는다

문제·비교·제품·고객 측정·초기 진입처럼 서로 다른 관계를 대표하는 장표를 먼저 렌더했다. 이후 상세본과 발표본 전체를 실제 PPTX 화면으로 확인했다. 그 과정에서 이미지 자체보다 이미지 밖의 캡션이 footer 선과 겹치는 문제, 캡션과 보조 문구가 붙는 문제, 아이콘 묶음의 옆 조각이 crop에 남는 문제를 찾았다.

수정한 PPTX는 다시 렌더했다. 변경된 PNG는 직접 재검수하고, 나머지는 처음 직접 읽은 이미지와 바이트가 같은지 비교했다. 이 방법은 최초 전체 검수를 생략하는 요령이 아니라 이미 수행한 검토를 정확히 이어받는 절차다. 원고나 출처가 바뀌면 이미지가 같더라도 관련 의미와 대본을 다시 확인한다.

## 재현할 작업 순서

1. 자료의 사실·가정·계획을 구별하고 질문별 논거와 누락을 정리한다.
2. 모든 장표의 주시각물·근거·자료 경로·가상 표기·한계·준비 상태를 정한다.
3. 원본·공식 자산을 조사하고 필요한 설명용 제품 자산을 기획·생성한다. 결과의 실제 내용과 사용권을 확인한다.
4. 제목·값·표·차트·설명·캡션은 편집 가능하게 만들고 이미지와 caption/footer 공간을 나눈다.
5. 대표 관계를 실제 PPTX로 확인한 뒤 양 덱 전체를 제작한다.
6. 모든 장표의 위계·근거 가독성·구성 변화와 기본 오류를 직접 검수한다.
7. 수정 렌더와 현재 해시를 확인하고 사업근거·디자인·발표·최종 상태를 구별해 전달한다.

구현을 재사용할 때는 특정 회사명·수치·슬라이드 ID가 들어간 출력 코드를 복사하지 않는다. 현재 장표의 blocks/items에서 문구와 값을 읽고, 실제 그린 블록만 coverage로 기록한다. 팔레트나 샘플의 숫자를 바꾸는 것보다 데이터와 구성의 연결을 유지하는 것이 중요하다.

자세한 실행 기준은 [증거 시각화 제작 절차](../plugins/seed-ir/skills/seed-ir/references/visual-production.md)에 있다. 이 절차에서 시각 pass는 읽을 수 있는 화면이라는 뜻이다. 실제 고객·제품·매출·팀 근거가 부족하면 결과는 그 한계를 명시한 초안으로 남는다.
